# 07 · 깊은 곳 탐험 (불가사의 던전식 로그라이트) — 기획안

> 상태: 초안 (검토 전) · 코드 변경 없음 · 작성 2026-09-30 · 의존: 없음 (메뉴 타일 자리 · 지속 HP · 시드 같은 공통 시스템은 → README.md)

## 1. 한 줄 요약 · 왜 재미있나

**지금 걷는 코스의 "깊은 곳"을 B1F부터 한 층씩 내려간다.** 층 사이 이동은 평소 타자(200걸음), 층에 닿으면 이벤트가 하나(야생 · 도구 · 함정 · 갈림길 · 휴식 · 켈리몬 상점 · 층의 주인). **HP · PP · 상태이상은 층을 넘어 그대로 이어진다.** 팀이 전멸하면 끝나고 주운 도구 절반을 잃는다. 스스로 나가면 전부 챙긴다. 도달한 층만큼 쌓이는 **탐험 포인트 → 탐험대 랭크**로 다음 런이 더 깊어진다.

- **걷기가 곧 진행**: 일하는 동안 팀 3마리가 HGSS 필드 도트로 줄지어 던전을 걷는다. 도착하면 `!` 하나가 뜨고, 들여다볼 때 처리하면 된다. 급하면 10W를 내고 **서두르기**.
- **결정은 짧고 굵게**: "더 내려갈까, 지금 나갈까"(위험을 걸고 더 가기), 갈림길 두 개 중 하나, 샘에서 HP냐 PP냐. 한 번 볼 때 5~60초면 된다.
- **레이더 · 타워는 한 판씩 끊어지지만 탐험은 몇 시간짜리 한 판이 이어진다**: 아침에 B1F로 들어가서 점심쯤 B10F 주인과 싸우는 식으로, "오늘의 이야기"가 하나 생긴다.
- **벌은 작다**: 포켓몬 · 경험치 · BP · 잡은 포켓몬은 절대 잃지 않는다. 잃을 수 있는 건 이번 런에서 주운 도구뿐이다.
- **시드로 재현된다**: 같은 탐험 코드 = 같은 층 구성. 나중에 친구와 같은 던전으로 겨루는 멀티의 바탕이 된다.

## 2. 원작(HGSS) 참고

| 원작 | 무엇 | 여기서 |
|---|---|---|
| HGSS **배틀캐슬**(배틀프런티어) | 배틀 사이에 HP · PP가 **회복되지 않고**, CP를 써서 회복하거나 도구를 얻는다 | 층 사이 HP · PP · 상태이상이 이어진다. 회복은 샘 · 도구 · 켈리몬 상점으로만 |
| HGSS **배틀룰렛**(배틀프런티어) | 배틀 전에 룰렛으로 무작위 효과(날씨 · 상태이상 · 도구 · BP)가 걸린다 | 층 이벤트 · 함정 추첨 |
| HGSS **배틀팩토리** | 대여 포켓몬, 모두 같은 레벨 | (3단계) 오늘의 던전 · 시드 대결의 **Lv.50 고정** 규칙 |
| HGSS **동굴탈출로프** · 어둠의 동굴 · 얼음 샛길 · 은빛산 | 동굴 안에서 쓰면 입구로 돌아가는 도구 | **무사히 나가는 도구**. 상점에서 팔고 던전에서도 줍는다 |
| **불가사의 던전 탐험대**(시간 · 어둠 2007, 하늘 2009 — 4세대 DS 시절) | B1F 표기, 계단, 몬스터하우스, 함정, 켈리몬 상점, 보물상자, 탐험대 랭크, 쓰러지면 도구를 잃음, 구조 메일 | 층 이벤트 대부분, 랭크, 도구 절반 손실. **구조 메일 → 멀티 확장**(8절) |
| 포켓워커 코스 | 코스별 출현표 · 도구표 | 던전 입구 = 지금 코스. 출현 · 도구는 그 코스 표 그대로 |

**바꾼 것**
- 칸 이동 · 턴제 탐색이 없다. LCD는 보는 화면이고 누르는 곳은 패널이라서 **층 하나 = 이벤트 하나**로 줄였다.
- 불가사의 던전의 배고픔 대신 **걸음**을 쓴다. 걸음은 어차피 들어오니까 걸음은 속도일 뿐이고, 아껴 써야 하는 건 HP · PP · 탐험 가방이다.
- 배틀은 이 앱의 4세대 싱글 배틀 엔진 그대로다(야생은 1:1, 내 쪽은 3마리까지 교체 가능).
- 한국판 명칭(배틀캐슬 · 배틀룰렛 · 배틀팩토리 · 켈리몬 · 몬스터하우스 · 탐험대 랭크 이름)은 **구현 전에 확인**한다.

## 3. 플레이 흐름

1. **메뉴 → "탐험" 타일**(노트: `최고 B7F` / 런 중이면 `B4F 도착!`). 해금 전에는 `누적 1,000W`라고 흐리게 보인다.
2. **로비**: LCD에는 코스 그림 속 동굴 입구와 팀. 패널에는 코스 이름 · 최고 층 · 랭크 · 팀 3칸(`party()`, 타워와 같음) · **[들어가기 · 50W] [나가기]**.
3. **이동(걷는 중)**: LCD에서 팀이 줄지어 걷는다(걸음이 들어오면 걷고, 멈추면 앞을 본다). 패널에는 `B3F → B4F · 120/200걸음`, 팀 HP 막대, **[서두르기 10W] [탐험 가방] [나가기]**. 이 화면을 떠나도(홈 · 레이더 · 타워 전부 가능) 걸음은 쌓인다.
4. **도착**: 홈 동료 머리 위에 `!`, 탐험 타일 노트가 `B4F 도착!`로 바뀐다. 보스 층에서만 알림이 온다. 도착한 뒤에는 이벤트를 처리할 때까지 걸음이 쌓이지 않는다(한 층 이상 미리 가지 않음).
5. **이벤트**(층마다 하나, 4절 표): 배틀은 기존 `.beats`/`.battle` 화면, 나머지는 패널 버튼 한두 개로 끝난다.
6. **끝**: 최하층 주인 격파(완주) · 스스로 나가기 · 전멸 → 결과 화면(도달 층 · BP · 챙긴 도구 · 탐험 포인트 · 랭크 막대) → 로비.

결과: LCD `B10F 완주!` + 보물상자 도트가 열리는 연출, 패널에 `+9 BP · 도구 7개 · 탐험 +30pt · 브론즈 ▓▓▓▓░ 실버까지 70`.

## 4. 규칙 · 수치 초안

### 4.1 입장 · 속도

| 항목 | 값 | 근거 |
|---|---|---|
| 해금 | 누적 **1,000W** (`earned`) | 어둑어둑 동굴이 열리는 때와 같음 |
| 입장료 | **50W** | 타워 `towerFee`와 같음 |
| 팀 | `party()` — 동료 + 가장 강한 2마리 | 타워와 같음 |
| 층 사이 거리 | **200걸음** (= 10W어치) | 20걸음 = 1W |
| 서두르기 | **10W** → 바로 도착 | 같은 비율. 붙어 앉아 한 번에 할 때 |
| 최하층 | 랭크에 따라 B10 → 15 → 20 → 25F | 4.4 |
| 층의 주인 | 5층마다(B5 · B10 · …), 최하층이 가장 셈 | |

**한 런(B10F)** = 이동 2,000걸음(하루 1만 타 기준 1~2시간 일하는 동안) + 들여다보기 10~12번(배틀 7판 × 1분 안팎, 나머지는 5~10초). 서두르기만 쓰면 100W로 15분 안에 끝낼 수 있다.

### 4.2 층 이벤트 (보스 층이 아닐 때, 시드로 뽑음)

| 이벤트 | 확률 | 내용 |
|---|---|---|
| 야생 포켓몬 | 35% | 1:1 야생 배틀(내 쪽 3마리 교체 가능). 이기거나 잡으면 층 통과 |
| 도구 | 20% | `courseItem`을 깊이에 맞춰(4.3) 뽑아 탐험 가방으로. 가방이 꽉 차면 하나를 버리거나 두고 감 |
| 갈림길 | 15% | 다음 층 이벤트를 2개 중 고름(골드 랭크부터 3개). 하나는 늘 `???`(함정 · 몬스터하우스 · 보물 중 하나) |
| 함정 | 10% | 독가시(팀 전원 독, 독 · 강철 타입 제외) · 낙석(전원 HP −1/8) · 끈적끈적(가방 도구 1개 사라짐) · 구멍(한 층 건너뜀, 보스 층은 못 건넘) |
| 샘(휴식) | 10% | 하나 고르기: 팀 HP 50% 회복 / PP 전부 + 상태이상 회복 (골드부터: 기절 1마리 HP 25%로 부활) |
| 몬스터하우스 | 5% | 야생 2~3판 연속(사이 회복 없음). 연쇄 1 · 2 · 3으로 쳐서 `chainShinyOdds` · `chainPerfectIVs` 적용, 이기면 도구 2개 |
| 켈리몬 상점 | 5% | 도구 3개를 W로(상점가 ×1.5, 상점에 없는 도구는 30W). 산 것은 탐험 가방으로 |

- **보정**: 샘이 4층 연속 안 나오면 다음 층은 샘(02의 `dry` 카운터와 같은 방식). B1F는 늘 야생.
- 층 구성은 시드 + 층 번호 + 갈림길 선택으로만 정해진다. 배틀 결과 · 걸음 · 시각은 섞이지 않는다(8절).

### 4.3 상대 · 보상

- **종**: 지금 코스 출현표 그대로. `encounter(&r)`를 `courseSteps = 층 × 500`인 **복사본 Walk**에 부른다. 깊을수록 희귀한 A · B 칸이 열리고(B6F = 3,000걸음 → 대부분 열림), 날씨 가중과 손님 10%도 그대로 적용된다.
- **레벨**: `L = max(코스 C칸 Lv, 팀 평균 − 5) + 층 ÷ 2`. 층의 주인은 L + 3, 최하층 주인은 L + 5. 이 세 값은 상수로 조정한다.
- **층의 주인**: 코스 A 그룹 종의 최종 진화형(`towerFoes`의 단계 규칙), **2V 확정**, 볼 효과 절반(전설과 같은 규칙). 잡을 수도 있다.
- **전설 코스의 최하층 주인** = 그 코스 전설. 아직 안 잡았으면 늘 나오고, 이미 잡았으면 **절반 확률**(나머지는 A 그룹 주인). 기존 "잡은 뒤엔 절반" 규칙과 같다. 3V, Lv.50(아르세우스 80).
- **이로치** 1/64(`shinyOdds`), 몬스터하우스만 연쇄 보정.
- **잡은 포켓몬**은 평소처럼 `keep()` → 워커/상자 · 도감으로 가고, **전멸해도 잃지 않는다**. 1단계에서는 팀에 합류하지 않는다(10절 Q7).
- **경험치 · 노력치**는 배틀마다 `writeBack` — 타워와 같고, 런이 어떻게 끝나든 남는다.
- **BP**: 도달 층 ÷ 2 + 주인 격파마다 2. B10F 완주 = 5 + 4 = **9BP**(타워 7연승 = 10BP와 비슷한 수준). 전멸해도 받는다.
- **보물상자**(완주 때): 코스에서 가장 희귀한 도구(`here.items[0]`) + 이상한사탕 1개, B20F 이상은 은색병뚜껑 1개를 더 준다.

### 4.4 끝나는 법 · 탐험 가방

| 끝 | 도구 | 비고 |
|---|---|---|
| 최하층 주인 격파(완주) | 전부 + 보물상자 | |
| 주인 격파 직후 "여기서 돌아갈까?" | 전부 | 5층마다 무료로 나갈 기회 |
| 동굴탈출로프 사용(아무 층) | 전부 | 상점 50W, 던전에서도 주움 |
| 전멸(부활초 · 기력의조각도 없음) / 로프 없이 기권 | **절반을 무작위로 잃음**(시드) | BP · 경험치 · 포켓몬은 그대로 |

- **탐험 가방**: 런 전용이고 6칸(실버부터 8칸). 던전 배틀에서는 **이 가방만 쓴다**. 원래 가방의 풀회복약 99개가 HP 누적 규칙을 무너뜨리지 않게 하려는 것이고, 반대로 원래 가방이 줄어들지도 않는다. 2단계에서는 입장할 때 원래 가방에서 3개까지 챙겨 갈 수 있다(잃을 수 있음).
- 볼: 기본 몬스터볼은 무한(지금과 같음), 탐험 가방의 볼이 먼저 쓰인다.

### 4.5 탐험대 랭크 (영구 해금)

탐험 포인트 = 층마다 1 + 주인 격파마다 5 + 완주 10. B10F 완주 = 30pt, B20F 완주 = 50pt.

| 랭크 | 누적 pt | 해금 |
|---|---|---|
| 노멀 | 0 | 최하층 B10F, 가방 6칸 |
| 브론즈 | 30 | 입장 때 상처약 ×2 |
| 실버 | 100 | 최하층 **B15F**, 가방 8칸 |
| 골드 | 250 | 갈림길 3갈래, 샘에서 부활 |
| 다이아 | 500 | 최하층 **B20F**, 입장 때 동굴탈출로프 ×1 |
| 슈퍼 | 1,000 | 켈리몬 상점 20% 할인 |
| 울트라 | 1,800 | 최하층 **B25F** |

## 6. 데이터 · 저장

```swift
// Walk에 추가 — 전부 Optional이라 옛 세이브는 nil로 읽힘
var dungeon: Dungeon? = nil          // 진행 중인 런 (nil = 없음)
var explorer: Int? = nil             // 누적 탐험 포인트 (랭크는 여기서 계산)
var deepest: [Int]? = nil            // 코스 번호별 최고 도달 층
var dungeonLog: [String]? = nil      // (3단계) 결과 코드 최근 20개

struct Dungeon: Codable, Equatable {
    var seed: UInt64, course: Int, depth: Int       // depth = 이번 런 최하층 (입장 때 랭크로 정함)
    var floor = 1, walked = 0                       // 지금 층, 다음 층까지 걸은 걸음 (0..<200)
    var arrived = true                              // 도착해서 이벤트를 기다리는 중 (이때는 걸음이 안 쌓임)
    var picks: [Int] = []                           // 갈림길 선택 — plan의 입력 (재현용)
    var team: [Member]                              // uid로 찾음 (놓아주거나 진화해도 안전)
    var bag: [String] = [], bp = 0, bosses = 0, dry = 0
    struct Member: Codable, Equatable { var uid: Int; var hp: Int; var pp: [Int]; var status: Status? }
}
```

- **`Walk.version`은 올리지 않는다.** `Store.load`는 버전이 다르면 세이브를 버리고 `Walk()`로 시작하기 때문이다. 필드는 Optional로만 추가한다.
- 한 번에 런은 하나. 코스를 바꿔도 런은 `Dungeon.course`로 계속 간다.
- 팀원이 사라지면(놓아주기) 그 멤버만 빠지고, 모두 없으면 런은 조용히 끝난다(도구 전부 돌려받음). 진화는 `writeBack`처럼 uid로 따라간다.
- HP · PP는 Mon이 아니라 `Dungeon.team`에 따로 둔다 → 런 중에 타워 · 레이더에 나가도 서로 섞이지 않는다.
- 층 구성은 저장하지 않는다. `plan(seed, course, floor, picks)`로 언제든 다시 만든다(세이브가 작아지고, 재현이 보장된다).

## 8. 멀티 확장 여지

**지금 설계로 지켜 둘 것** (멀티가 없어도 비용이 거의 없음)
1. `plan()`은 **순수 함수**: 입력은 `(seed, course, floor, picks)`와 `planVersion`뿐이다. 날짜 · 걸음 · 날씨 · 배틀 결과는 넣지 않는다(날씨 가중은 층 번호로 정한 "던전 날씨"로 바꿈).
2. 레벨만 팀 평균에 따라 다르다 → 겨루는 모드는 **Lv.50 고정**(배틀팩토리 방식: 배틀용 Mon 복사본의 레벨만 50, 경험치는 안 씀).
3. 시드는 **40비트 → 8글자 탐험 코드**(Crockford base32, `K7QM-2XRA`). 입력하면 같은 던전.
4. 배틀 난수도 런 시드에서 파생시킨다(`Seeded(s: seed ^ floor << 20 ^ turn)` — 03의 `fightRng` 분리가 먼저, → 03-raid.md §5) → `(코드 + 입력 기록)`으로 런 전체를 재생할 수 있다. `Sources/Model` · `Battle`은 Foundation만 써서 **리눅스 Swift로 서버 검증**도 가능하다.

**단계별 소셜**
- **서버 없이(3단계)**: ① 탐험 코드 복사 · 붙여넣기(메신저로 "이 코드 B15F 가 봐"). ② **오늘의 던전**: 날짜로 시드와 코스를 정하고 Lv.50 고정 → 모든 사람이 같은 던전, 결과 문자열(`PW7-20261001-B14-T212-체크섬`)로 비교.
- **구조 요청(불가사의 던전 구조 메일)**: 전멸하면 SOS 코드(런 시드 + 층)가 생긴다 → 친구가 자기 팀으로 **그 층만** 플레이해서 이기면 A-OK 코드를 돌려준다 → 입력하면 그 층에서 부활해 이어서 간다(잃은 도구도 복구). 서버 없이 코드 두 줄로 되는 비동기 협동이다. 위조는 체크섬 정도만 막는다(친구끼리니까).
- **작은 서버(4단계, 필요할 때)**: 오늘의 던전 순위 = `POST {code, floor, turns, inputLog}` → 서버가 리눅스 Swift로 재생해서 검증한다. Cloudflare Worker + KV 정도면 된다. 친구 코드는 03의 `trainerID`(무작위 64비트, → 03-raid.md §6)로.

## 10. 리스크 · 열린 질문 (권장 기본값)

1. **던전 배틀에서 원래 가방을 쓸 수 있나?** → 기본: **탐험 가방만**(2단계에서 3개 챙기기). 원래 가방을 열면 HP 누적의 긴장이 사라진다.
2. **전멸 페널티는?** → 기본: **주운 도구 절반**. 대안: 0(아예 무벌) / 전부(불가사의 던전 원작).
3. **팀은 자동(`party()`)인가, 직접 고르나?** → 기본: 자동(타워와 같음). 직접 고르기는 3단계에 로비의 팀 칸을 클릭하는 방식으로.
4. **층 거리 200걸음 · 서두르기 10W가 맞나?** → 기본 그대로. 하루 타자 수가 적으면 150걸음으로.
5. **도착할 때마다 알림?** → 기본: **보스 층 도착 · 전멸 대기만 알림**, 보통 층은 `!`와 타일 노트만. 하루 10번 알림은 방해가 된다.
6. **런 중에 도망은?** → 기본: 없음(그 자리에 교체). 도망을 허용하면 층을 공짜로 넘길 수 있다.
7. **잡은 포켓몬이 팀에 합류(불가사의 던전 영입)?** → 기본: 1단계엔 없음(도감 · 상자로만). 원하면 2단계에 "기절한 팀원 자리를 대신할까?"로.
8. **주인을 잡을 수 있나?** → 기본: 가능, 볼 효과 절반, 2V. 막으면 엔진에 볼 금지 플래그가 하나 더 필요하다.
9. **난이도 공식(평균 − 5 + 층 ÷ 2)** → 기본 그대로, 상수 3개로 조정. 1단계 출시 뒤 3~4런 해 보고 맞춘다.
10. **메뉴 새 타일 vs 배틀 타워 로비 안에 넣기** → 기본: 타일 "탐험"(다른 기획과 합쳐 13칸 2×7, → README.md '메뉴 타일'). 타일이 늘어나는 게 싫으면 타워 로비에 [타워 | 탐험] 탭.
11. **오늘의 던전을 잠긴 코스에서도 열까?** → 기본: 예(Lv.50 대여 규칙이라 코스 해금과 무관, 출현 종은 도감 "봤음"으로만). 아니면 첫 2코스 중에서만.
12. **리스크 — 세이브**: `version`을 올리면 옛 세이브가 사라진다 → 올리지 않고 Optional로만 추가한다(6절). 실제 세이브에서는 절대 테스트하지 않는다(셀프테스트는 임시 파일 사용).
13. **리스크 — 밸런스**: 3 대 1 야생은 쉬울 수 있다 → HP 누적 + 샘 10%로 소모전을 만든다. 그래도 쉬우면 주인만 2마리(트레이너식 3 대 2)로.
