## 2. 우편함

### 2.1 우편 하나

```swift
struct Mail { id, kind, from, title, body?, gifts: [Gift], at, read, claimed }
enum Gift {
    case mon(Mon)                                   // 포켓몬 (교환으로 받은 것 · 돌아온 것 · 맡겼다 돌아온 것 · 보상)
    case items(String, Int)                         // 도구 n개
    case bp(Int), watts(Int)
    case title(String)                              // 칭호 ("타워 타이쿤")
    case deco(String)                               // 트레이너 카드 장식: "silver" · "gold"
    case pickItem([String])                         // 이 중 하나 고르기 (14연승)
    case pickLegend([Int], level: Int, shiny: Bool) // 이 중 한 종 고르기: 고를 때 서버가 만든다 (100연승)
}
```

- `kind`: `trade`(교환으로 받은 포켓몬) · `returned`(내 글 · 제안의 포켓몬이 돌아옴) · `visit`(맡겼다 돌아옴, 키운 걸음은 body) · `tower`(연승 보상) · `notice`(공지, 선물 없음) · `admin`(운영자 지급).
- 표는 `mail (id, key, kind, from_name, title, body, gifts JSON, at, read_at, claimed_at)`. 포켓몬은 받을 때 장부(`mons`)에 올린다(지금 받기 함과 같다).

### 2.2 API와 act

| 무엇 | 모양 |
|---|---|
| 목록 | `POST /v2/mail {id, session, read?: [mail id]}` → `MailReply {mails, unread}`. `read`로 연 우편을 읽음으로 |
| 받기 | `"act": {"mailClaim": {"id", "pick"?}}` — 선물 전부를 받는다. 고르기가 있으면 `pick`(목록의 몇 번째)이 있어야 한다 |
| 모두 받기 | `"act": {"mailClaimAll": {}}` — 고르기가 없는 우편만 한꺼번에 |
| 새 우편 알림 | news `mailNew {id, title}`(3.9 앱만). 앱은 이걸 받거나 켤 때 `/v2/mail`을 읽는다 |

- cannot: "이미 받았어요" · "하나를 골라 주세요" · "받을 수 없는 우편이에요"
- 교환 진화(지닌 도구)와 맡기기 경험치 · 진화는 지금 받기 함처럼 **받을 때** 일어난다.

### 2.3 보관

| 우편 | 보관 |
|---|---|
| 선물이 있는 우편 | **받을 때까지 사라지지 않는다** |
| 받은 우편 · 선물 없는 우편(읽음) | 30일 뒤 정리 |
| 읽지 않은 공지 | 90일 |

### 2.4 앱 화면

§6(pokewalker mac 초안)에 있다.

### 2.5 운영자

- `pw mail <id> --title "…" [--body "…"] [--item 이름 n] [--bp n] [--watts n] [--title-gift 칭호]`: 한 명에게.
- `pw mail --all …`: 모두에게(테스트 ID 빼고). 보낸 기록은 `pw mail-log`.

## 3. 배틀 타워 연승 최초 보상

### 3.1 보상표

| 14 | 지닌 도구 1개 고르기: 구애머리띠 · 구애안경 · 구애스카프 · 생명의구슬 · 기합의띠 · 먹다남은음식 · 달인의띠 |

| 70 | 트레이너 카드 **금장식** |
| 100 | 칭호 **"타워 타이쿤"** + **이로치 확정 전설** 1마리 고르기(게임에 나오는 전설 35종: 코스 33 + 상점의 뮤츠 · 칠색조, Lv.70 · 4V) |

- **한 번만**: 서버의 지급 기록 `tower_rewards (key, wins, at)`. 연승이 끊겼다가 다시 닿아도 또 주지 않는다.
- 언제: 그 승리의 act가 끝날 때 서버가 `towerBest`를 보고 아직 안 받은 구간을 우편으로 보낸다.
- **소급**: 같은 검사를 모든 act에서 한다. 그래서 배포 뒤 첫 act에 이미 넘은 구간이 우편으로 온다(지금 기록: 경환 최고 8연승 → 7연승 보상, 김지훈 26연승 → 7 · 14 · 21연승 보상). 3.9 전 앱도 우편은 쌓이고, 받기만 3.9에서.
- **보이게**: 타워 로비에 보상 띠(§6 E). 서버가 `Walk.towerRewards: [Int]?`(받은 구간)를 세이브에 같이 둔다.

### 3.2 칭호와 장식

- 세이브에 `titles: [String]?`(얻은 칭호), `deco: String?`("silver" · "gold", 더 좋은 것만 남김).
- `TeamCard`에 `title: String?` · `deco: String?`이 붙는다. **내 트레이너 카드 · 친구 목록 · 친구 카드**에 보인다(§6 C).
- 제안: 이름이 나오는 곳 중 **대전 상대 이름 옆**에도 칭호를 붙인다(이름과 함께 보이는 유일한 1:1 화면). 게시판 · 레이드는 나중에.

## 4. 예전 앱 (3.8.x 이하)

- MIN_APP은 올리지 않는다. 3.9 전 앱에는 **아무것도 자동으로 들어가지 않는다**(사용자). 우편은 쌓이고, 3.9로 업데이트하면 우편함에서 받는다.
- 3.8.x: `/v2/market`의 `claims`는 늘 비어 있다. `claim(id:)`는 "우편함에서 받아요 / (3.9로 업데이트)", `mailClaim`은 "우편함은 3.9부터예요".
- 예전 앱에 우편이 왔다고 알리는 방법: 따로 두지 않는다. 3.8.x 앱은 자동 업데이트가 6시간 안에 3.9를 받아 다음 실행 때 바꾸고, 자동 업데이트가 막힌 PC(3.8.5+)는 "3.9 버전이 나왔어요" 배너를 띄운다. 교환이 되면 오는 소식(`tradeClosed`)의 문구는 "교환이 성립했어요 · 우편함에서 받아요".

### A. 우편함
- 들어가는 곳: 1단의 **우편함** 칸(바로 열림). 빨간 점: 안 읽은 우편이나 받을 게 남은 우편(서버의 `unread`). 줄: "받을 우편 n통" · "새 우편 n통" · "보상 · 공지".
- 새 우편(news `mailNew`)은 화면을 가로채지 않고 빨간 점과 알림 한 번. 새 알림 종류 "우편"(우클릭 → 알림에서 끌 수 있음).
- 목록: 한 쪽 6줄에 쪽 넘김. 순서는 서버 그대로(받을 것 먼저, 그다음 최근).
  - 각 줄: 아이콘(보상 = 상자, 공지 = 종이, 교환 · 맡기기 = 그 포켓몬), 제목, 보낸 곳 · 날짜, 첨부 칩, 안 읽음 점. 받은 우편은 흐리게 "받음".
  - 아래 버튼 **모두 받기**(고르기 우편은 빼고). 받을 게 없으면 흐림.
- 우편 하나: 제목, 보낸 곳 · 날짜, 본문(여러 줄), 첨부 목록, **받기**(공지는 버튼 없음, 받은 뒤엔 "받음"). 열면 읽음(`/v2/mail`의 `read`). LCD에는 첨부(포켓몬 스프라이트 · Lv, 도구 이름 · 개수, 메달).
- 받기 결과: "○○을 받았다!" (포켓몬은 "/ 상자로 보냈다"), 교환 포켓몬은 그때 통신 진화, 레벨 · 기술은 홈 뉴스로(3.8 받기 함과 같다).

### B. 교환 메뉴 (받기 탭을 뺀 뒤)
- 탭은 전체 · 내 글 · 내 제안. 교환 칸의 빨간 점은 내 글의 새 제안만.
- 받던 것은 모두 우편의 포켓몬 첨부로 온다(교환으로 받은 것 · 돌아온 것 · 맡기기에서 돌아온 것, 맡기기는 키운 걸음 `steps`가 받을 때 경험치로).
- 게시판 아래 문구: "교환으로 받은 포켓몬은 우편함으로 와요".

### C. 장식 · 칭호
- 트레이너 카드 LCD 첫 쪽: 은장식(50) · 금장식(70)은 LCD 바깥 1도트 테두리 무늬와 이름 옆 7×7 메달. 칭호는 이름 아래 작은 글씨. 흑백 LCD에선 밝기 단계로.
- 트레이너 카드 패널: 탭 위에 칭호 배지(금색 알약)와 장식 이름. 높이 230 → 254.
- 친구 목록 줄: 이름 옆 메달, 칭호는 공간이 있으면 줄 아래. 친구 카드: 제목 옆 메달, 그 아래 칭호 알약. LCD의 친구 카드에도 메달.
- 대전: 상대 이름 옆 칭호(`DuelView.opponentTitle`, 장식은 없음).

### D. 고르기 (14연승 지닌 도구 · 100연승 전설)
- 우편의 **받기**를 누르면 고르기 화면.
- 지닌 도구: 일곱 줄이 한 쪽에(이름 + 효과 한 줄, 도구 주기 줄 모양) — 후보 일곱 가지(구애머리띠 · 구애안경 · 구애스카프 · 생명의구슬 · 기합의띠 · 먹다남은음식 · 달인의띠). 처음 누르면 LCD에 설명, 한 번 더 누르면 "받을까요?" 아니오/예.
- 전설: 포켓몬 메뉴와 같은 격자(★ 이로치 확정) — 후보는 `Tower.legends` 35종(코스의 33 + 상점의 뮤츠 · 칠색조, Lv.70 · 4V · 이로치)이라 6×4 격자 두 쪽. 이미 가진 종도 **흐리게 하지 않는다**(④). 처음 누르면 LCD에 그 전설(이로치), 한 번 더 누르면 확인.

### E. 타워 화면
- 로비에 보상 띠: 7 · 14 · 21 · 28 · 35 · 50 · 70 · 100(`Tower.rewards`). 받은 구간(`Walk.towerRewards`)은 초록 체크, 다음 구간은 빨간 테두리, 칸 아래 짧은 보상 이름(사탕×3 · 도구 · 은뚜껑 …), 띠 위에 다음 보상을 말로. 패널 높이 353 → 400. LCD 제목 줄 오른쪽에 "다음 보상 21연승".
- 다음 판이 타이쿤전(`Tower.tycoonFights.contains(towerStreak + 1)`)이면 로비 버튼이 "타워 타이쿤에게 도전"(금색).
- 등장 연출: 화면 반전 플래시 → 트레이너 등장(`palmer`) "타워 타이쿤이 승부를 걸어왔다!". 로비(타이쿤 차례)와 배틀 내내 LCD 테두리가 은(49) · 금(99) 무늬. 제목 줄 "타워 타이쿤 (은 / 금) · 타이쿤전 · 남은 n : m". 보스전은 `battle.trainer == Tower.tycoon`.
- 승리: "타워 타이쿤을 이겼다!"와 BP(두 배). 보상 우편이 오면 "우편함에 보상이 왔다" 한 줄 더.

## 7. 야생 배틀 경험치: 워커도 (사용자, 3.9)

- 상대와 마주친 포켓몬: 지금과 같다(마주친 수로 나눈 몫, 각자 자기 레벨로, 노력치 전부). 학습장치가 있어도 줄지 않는다.
- **나가지 않은 우리 포켓몬(살아 있는 워커 · 동료)**: 각자 자기 레벨로 계산한 그 몫의 **절반**, 노력치는 없다(6세대 학습장치 방식).
- **학습장치**를 지닌 포켓몬: 나가지 않았어도 **한 몫 전부와 노력치**.
- 행복의알 ×1.5는 그대로. 타워 · 대전 · 레이드는 경험치 없음 그대로.
- 레벨 차이: 경험치 공식이 이미 낮은 레벨에 많이, 높은 레벨에 적게 준다(5세대 공식 × 0.5). 워커 몫은 거기에 다시 절반이라 지나치게 빠르지는 않다. 데이터를 보고 조정한다.
- 화면: 배틀 끝에 경험치 줄이 여러 개 나온다(`gained` beat가 포켓몬마다). 앱(0a2ff62)은 나가 있는 포켓몬의 줄과 레벨업은 그대로 두고, 나머지는 "다른 포켓몬도 경험치를 받았다!" 한 줄로 묶는다(`Walker.shown`).
