## 2. 우편함

### 2.1 우편 하나

```swift
struct Mail { id, kind, from, title, body?, gifts: [Gift], at, read, claimed }
enum Gift {
    case mon(Mon)                                   // 포켓몬 (교환으로 받은 것 · 돌아온 것 · 맡겼다 돌아온 것 · 보상)
    case items(String, Int)                         // 도구 n개
    case bp(Int), watts(Int)
    case title(String)                              // 칭호 ("타워 타이쿤")
    case deco(String)                               // 트레이너 카드 장식: "silver" · "gold"
    case pickItem([String])                         // 이 중 하나 고르기 (14연승)
    case pickLegend([Int], level: Int, shiny: Bool) // 이 중 한 종 고르기: 고를 때 서버가 만든다 (100연승)
}
```

- `kind`: `trade`(교환으로 받은 포켓몬) · `returned`(내 글 · 제안의 포켓몬이 돌아옴) · `visit`(맡겼다 돌아옴, 키운 걸음은 body) · `tower`(연승 보상) · `notice`(공지, 선물 없음) · `admin`(운영자 지급).
- 표는 `mail (id, key, kind, from_name, title, body, gifts JSON, at, read_at, claimed_at)`. 포켓몬은 받을 때 장부(`mons`)에 올린다(지금 받기 함과 같다).

### 2.2 API와 act

| 무엇 | 모양 |
|---|---|
| 목록 | `POST /v2/mail {id, session, read?: [mail id]}` → `MailReply {mails, unread}`. `read`로 연 우편을 읽음으로 |
| 받기 | `"act": {"mailClaim": {"id", "pick"?}}` — 선물 전부를 받는다. 고르기가 있으면 `pick`(목록의 몇 번째)이 있어야 한다 |
| 모두 받기 | `"act": {"mailClaimAll": {}}` — 고르기가 없는 우편만 한꺼번에 |
| 새 우편 알림 | news `mailNew {id, title}`(3.9 앱만). 앱은 이걸 받거나 켤 때 `/v2/mail`을 읽는다 |

- cannot: "이미 받았어요" · "하나를 골라 주세요" · "받을 수 없는 우편이에요"
- 교환 진화(지닌 도구)와 맡기기 경험치 · 진화는 지금 받기 함처럼 **받을 때** 일어난다.

### 2.3 보관

| 우편 | 보관 |
|---|---|
| 선물이 있는 우편 | **받을 때까지 사라지지 않는다** |
| 받은 우편 · 선물 없는 우편(읽음) | 30일 뒤 정리 |
| 읽지 않은 공지 | 90일 |

### 2.4 앱 화면

§6(pokewalker mac 초안)에 있다.

### 2.5 운영자

- `pw mail <id> --title "…" [--body "…"] [--item 이름 n] [--bp n] [--watts n] [--title-gift 칭호]`: 한 명에게.
- `pw mail --all …`: 모두에게(테스트 ID 빼고). 보낸 기록은 `pw mail-log`.

## 3. 배틀 타워 연승 최초 보상

### 3.1 보상표

| 연승 | 보상 |
|---|---|
| 7 | 이상한사탕 3 |
| 14 | 지닌 도구 1개 고르기: 구애머리띠 · 구애안경 · 구애스카프 · 생명의구슬 · 기합의띠 · 먹다남은음식 · 달인의띠 |
| 21 | 은색병뚜껑 |
| 28 | 금색병뚜껑 |
| 35 | 150BP |
| 50 | 트레이너 카드 **은장식** + 금색병뚜껑 |
| 70 | 트레이너 카드 **금장식** |
| 100 | 칭호 **"타워 타이쿤"** + **이로치 확정 전설** 1마리 고르기(게임에 나오는 전설 33종 중, Lv.70 · 4V) |

- **한 번만**: 서버의 지급 기록 `tower_rewards (key, wins, at)`. 연승이 끊겼다가 다시 닿아도 또 주지 않는다.
- 언제: 그 승리의 act가 끝날 때 서버가 `towerBest`를 보고 아직 안 받은 구간을 우편으로 보낸다.
- **소급**: 같은 검사를 모든 act에서 한다. 그래서 배포 뒤 첫 act에 이미 넘은 구간이 우편으로 온다(지금 기록: 경환 최고 8연승 → 7연승 보상, 김지훈 26연승 → 7 · 14 · 21연승 보상).
- **보이게**: 타워 로비에 보상 띠(§6 E). 서버가 `Walk.towerRewards: [Int]?`(받은 구간)를 세이브에 같이 둔다.

### 3.2 칭호와 장식

- 세이브에 `titles: [String]?`(얻은 칭호), `deco: String?`("silver" · "gold", 더 좋은 것만 남김).
- `TeamCard`에 `title: String?` · `deco: String?`이 붙는다. **내 트레이너 카드 · 친구 목록 · 친구 카드**에 보인다(§6 C).
- 제안: 이름이 나오는 곳 중 **대전 상대 이름 옆**에도 칭호를 붙인다(이름과 함께 보이는 유일한 1:1 화면). 게시판 · 레이드는 나중에.

### 3.3 보스전: 타워 타이쿤

| 언제 | 상대 |
|---|---|
| **49번째** 배틀(48연승 상태) | 타워 타이쿤 (은): 드사이돈 · 밀로틱 · 망나뇽 — Lv.50, 6V, 노력치 252/252, 좋은 4기술, 지닌 도구 |
| **99번째** 배틀(98연승 상태) | 타워 타이쿤 (금): 망나뇽 · 밀로틱 · 메타그로스 — 같은 조건에 더 좋은 도구 · 성격, AI가 무작위로 고르지 않음 |

- 이길 때마다 보스는 그 연승 때 또 나온다(원작처럼). 보스 승리는 **BP 두 배**.
- 그림: Showdown 트레이너 그림 `palmer`(4세대 타워 타이쿤)를 다른 타워 트레이너처럼 `frames.bin`에 넣는다(`tools/gen.py`).
- 연출(앱): 들어올 때 "타워 타이쿤이 승부를 걸어왔다!", 이기면 "타워 타이쿤을 쓰러뜨렸다! (은 / 금)" 한 장면 더.

## 4. 예전 앱 (3.8.x 이하)

## 6. 앱 화면 (pokewalker mac 초안)

### A. 우편함
- 들어가는 곳: **보류** — 메뉴를 2단계로 바꾸는 검토(사용자, 2026-10-08)와 함께 정한다. 후보:
  - 메뉴 타일(지금 12칸이면 13번째, 2×7 → 홈 높이 406 → 438, 상태 시트에 "우편 · 안 읽은 n통" 한 줄)
  - 2단계 메뉴의 그룹 안(예: 친구 · 교환과 같은 그룹)
  - 홈 제목 줄의 ✉ 아이콘(키보드로 갈 길이 따로 필요)
  - 어느 쪽이든 빨간 점은 그 자리(그룹이면 그룹 칸에도)에 뜬다.
- 빨간 점: 안 읽은 우편이나 받을 게 남은 우편이 있으면 우편함 타일에. 새 우편은 화면을 가로채지 않고 배너만 한 번. 새 알림 종류 "우편"(끌 수 있음).
- 목록: 한 쪽 6줄에 쪽 넘김.
  - 각 줄: 아이콘(보상 = 상자, 공지 = 종이, 교환 · 맡기기 = 그 포켓몬), 제목, 보낸 곳, 날짜, 첨부 칩, 안 읽음 점.
  - 받은 우편은 흐리게 "받음". 탭은 없고, 받을 것 먼저 그다음 최근 순.
  - 아래에 **모두 받기**(고르기 우편은 빼고).
- 우편 하나: 제목, 본문, 첨부, **받기**(공지는 버튼 없음). LCD에는 첨부(포켓몬 스프라이트, 도구 이름 · 개수, 메달 그림).
- 받기 결과는 지금 받기 함과 같다: "○○을 받았다! / 상자로 보냈다". 교환 포켓몬은 그때 통신 진화한다.

### B. 교환 메뉴 (받기 탭을 뺀 뒤)
- 탭은 전체 · 내 글 · 내 제안. 교환 타일의 빨간 점은 내 글의 새 제안만.
- 받던 것은 모두 우편의 포켓몬 첨부로 온다(교환으로 받은 것 · 돌아온 것 · 맡기기에서 돌아온 것).
- 게시판 아래 문구: "교환으로 받은 포켓몬은 우편함으로 와요".

### C. 장식 · 칭호
- 트레이너 카드 LCD 첫 쪽: 은장식(50) · 금장식(70)은 LCD 바깥 1도트 테두리 무늬와 이름 옆 7×7 메달. 칭호는 이름 아래 작은 금색 글씨. 흑백 LCD에선 밝기 단계로.
- 트레이너 카드 패널: 탭 위에 칭호 배지(금색 알약)와 장식 이름. 높이 230 → 254.
- 친구 목록 줄: 이름 옆 메달, 칭호는 공간이 있으면 줄 아래. 친구 카드: 제목 옆 메달, 그 아래 칭호 알약. LCD의 친구 카드에도 메달.
- 대전 상대 이름 옆 칭호(§3.2 제안).

### D. 고르기 (14연승 지닌 도구 · 100연승 전설)
- 우편의 **받기**를 누르면 고르기 화면.
- 지닌 도구: 한 쪽 6줄(이름 + 효과 한 줄, 도구 주기 줄 모양) — 후보는 32BP 일곱 가지(구애머리띠 · 구애안경 · 구애스카프 · 생명의구슬 · 기합의띠 · 먹다남은음식 · 달인의띠)라 한 쪽에 다 들어간다. 처음 누르면 LCD에 설명, 한 번 더 누르면 "받을까요?" 아니오/예.
- 전설: 포켓몬 메뉴와 같은 격자(★ 이로치 확정) — 후보는 게임에 나오는 전설 33종(Lv.70 · 4V · 이로치)이라 6×4 격자 두 쪽. 처음 누르면 LCD에 그 전설, 한 번 더 누르면 확인.
- 이미 가진 종: **흐리게 표시만 하고 고를 수는 있게**(추천: 이로치라 새로 가질 이유가 있다).

### E. 타워 화면
- 로비에 보상 띠: 7 · 14 · 21 · 28 · 35 · 50 · 70 · 100. 받은 구간은 체크, 다음 구간은 강조, 칸 아래 보상 이름. 패널 높이 353 → 393. LCD에는 "다음 보상 21연승".
- 48 · 98연승 뒤 로비 버튼: "타워 타이쿤에게 도전"(금색).
- 등장 연출: 금색 플래시 → "타워 타이쿤이 / 승부를 걸어왔다!" → 트레이너 등장(금색 테두리 · 반짝임) → 제목 줄 "배틀 타워 · 타이쿤전", HUD의 상대 이름 금색.
- 승리: "타워 타이쿤을 이겼다!"와 BP(두 배). 보상 우편이 오면 "우편함에 보상이 왔다" 한 줄 더.

### F. 앱이 서버에서 받는 것 (§2 · §3과 같은 이름)
- `POST /v2/mail` → `MailReply {mails: [Mail], unread}`, `Mail {id, kind, from, title, body?, gifts, at, read, claimed}`
- act `mailClaim(id:pick:)`, `mailClaimAll`, news `mailNew(id:title:)`
- `Walk.towerRewards`, `Walk.titles`, `Walk.deco`; `TeamCard.title`, `TeamCard.deco`
- 3.8.x 앱: 서버가 선물을 바로 세이브에 넣는다(§4).
