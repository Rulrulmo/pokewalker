# 12 멀티: 팀 보기 · 교환 · 협동 레이드 · 실시간 대전

> 2026-10-04 · **확정**(사용자: "ㅇㅇ 추천대로 가면될것같아"). 3.0(11)에서 서버가 세이브를 만들게 되면서 멀티의 걸림돌(세이브를 믿을 수 없음)이 없어졌다. 이 문서가 서버(미니 PC의 Claude)와 앱(릴리스 Mac의 Claude) 사이의 계약이다.

## 0. 정한 것

| 항목 | 결정 |
|---|---|
| 순서 | **M1** 팀 보기 · 순위 · 놀러 오는 동료 → **M2** 교환 → **M3** 협동 레이드 → **M4** 실시간 대전 |
| 규모 | 팀 16명 이상 |
| 부계정 | 막지 않는다(같은 팀을 믿는다) |
| 방식 | M1~M3은 비동기(각자 편할 때, 결과가 쌓임). M4만 둘이 동시에 |
| 레이드 | HP는 지난주 참가 인원에 맞춰 자동(목요일쯤 잡히게), 잡으면 그 주는 끝, 기여 순위(이름 · %)는 공개 |
| 교환 | 통신교환 진화는 진짜 교환 때 일어난다(혼자 누르는 "통신 진화" 버튼은 M2에서 없앤다) |

## 1. 공통: 옛 앱이 깨지지 않게

- 새 News 종류를 옛 앱(3.1.x)에 보내면 `ActReply`의 디코딩이 통째로 실패한다(모르는 enum case). 그래서 **`ActReq`에 `app`(앱 버전, 선택 칸)** 을 더한다. 서버는 그 버전이 아는 것만 보낸다(`hello`는 3.2부터 등). 옛 앱은 `app`을 보내지 않으니 아무것도 새로 받지 않는다.
- 앱도 앞으로는 news 배열을 **하나씩** 디코딩하고 모르는 것은 건너뛴다(다음 추가부터는 버전 분기가 필요 없게).
- 남의 것을 읽는 요청은 순서가 없으니 seq 밖이다: `POST /v2/team`(아래). 남에게 영향을 주는 것(인사, 교환, 레이드 데미지)은 `/v2/act`의 행동이다.

## 2. M1 — 팀 보기 · 순위 · 놀러 오는 동료 · 인사

### 2.1 팀 목록 `POST /v2/team {"id", "session"}` → `TeamReply {"week": "2026-W40", "cards": [TeamCard]}`
세션이 맞아야 한다(409 replaced 등은 v2와 같다). 서버는 10초 동안 같은 답을 재사용한다. 3.0에서 한 번이라도 행동한 트레이너만 나온다(2.x에 머문 ID는 빠짐).

`TeamCard`(공유 코드 `Sources/Model/Team.swift`, 합성 Codable):

| 칸 | 내용 |
|---|---|
| `name` | 트레이너 ID(표시 이름) |
| `companion` | 동료 `Mon` 전체(그림, 이로치, 레벨, 성별) |
| `walker` | 워커의 포켓몬(최대 3) |
| `owned`, `seen`, `shinies` | 도감 잡음 · 봤음 · 이로치로 잡은 종 수 |
| `today`, `week` | 서버가 센 오늘 · 이번 주(월~일, KST) 걸음 |
| `total` | 누적 걸음 |
| `towerBest`, `bestChain`, `bp` | 타워 최고 연승, 최고 연쇄, BP |
| `course` | 지금 코스 번호 |
| `idle` | 마지막 행동에서 지난 초(앱이 켜져 있으면 15초마다 걸음을 보내니 60초 안이면 "지금 걷는 중") |

### 2.2 앱이 할 것(서버는 데이터만)
- **팀 화면**(메뉴 새 타일 "팀"): 카드 목록(지금 걷는 중이 위), 누르면 그 사람의 트레이너 카드(동료 크게, 워커 3마리, 도감 · 타워 · 연쇄 · 걸음).
- **주간 순위**: 이번 주 걸음 · 도감 잡음 · 타워 최고 연승 탭. `cards`를 앱이 정렬한다(16명 이상이면 상위 10명 + 나).
- **놀러 오는 동료**: 팀 목록을 몇 분마다 받아 두고, 홈에서 가끔(예: 300~600걸음마다) 지금 걷는 중인 팀원의 동료가 수첩에 작은 스티커로 들렀다 간다. "민수의 리자몽이 놀러 왔다!" 누르면 인사(아래).

### 2.3 인사 `"act": {"greet": {"to": "민수"}}`
- 서버: 받는 사람의 `inbox`에 넣는다(보낸 이, 보낸 이의 동료 종 · 이로치). 같은 사람에게는 1시간에 한 번(넘으면 `cannot`: "조금 뒤에 다시\n인사할 수 있어요"). 자기 자신 · 없는 ID는 `cannot`.
- 받는 사람: 다음 행동(15초 안의 걸음)의 답 news에 `hello {from, dex, shiny}`. 홈에서 "민수가 인사했다! ♥"와 그 동료 스티커. 하루 지난 인사는 버린다.

## 3. M2 — 교환 (개요, M1 뒤에 자세히)
- 상자의 포켓몬만(동료 · 워커는 상자로 보낸 뒤). 제안(`trade offer {to, give: uid, want: uid?}`) → 받는 쪽 news → 수락(`trade accept {offer, give: uid}`) 또는 거절. 서버가 두 세이브를 한 트랜잭션에서 바꾼다. 24시간 지나면 제안은 사라진다.
- uid는 트레이너마다 따로 매기므로 받는 쪽에서 새 uid를 받는다. 발급 장부: 준 쪽 `traded`, 받은 쪽 `trade`(어디서 왔는지). `Mon.ot`(어버이, Optional)를 더해 포켓몬 페이지에 "어버이: 민수".
- 통신교환 진화: 받는 순간 그 종의 교환 진화(필요한 도구 포함)가 맞으면 받는 쪽에서 진화(news `evolve`).

## 4. M3 — 협동 레이드 (개요, 03 기획을 팀판으로)
- 월요일 0시(KST)에 서버가 이번 주 보스(종 · ★ · 레벨)를 정한다. 다음 주 보스도 미리 보인다.
- 파워: 1,000걸음 = 1칸(최대 3칸). 한 판 = 파워 1칸, 타워 파티 3마리, 최대 6턴, 한 판에 최대 3줄. 서버가 돌린다(`/v2/act`의 레이드 행동).
- 팀 HP = 줄 수 × 1줄 HP. 줄 수는 **지난주 한 판이라도 싸운 인원**(첫 주는 지금 팀 인원)에 맞춰 목요일쯤 잡히게(수치는 M3에서 시뮬레이션으로).
- 다 깎이면 그 주는 끝: 한 판이라도 싸운 사람 모두 포획 기회(볼 3 + 기여 상위는 +1~2), 개체는 각자 따로(4V, 이로치 1/64). 클리어 보상(BP · 이상한사탕 · ★5 은색병뚜껑), 판마다 BP.
- 로비: 팀 HP 바, 남은 날, 오늘 팀이 깎은 양, 기여 순위(이름 · %), 최근 공격.

## 5. M4 — 실시간 대전 (개요)
- 팀 화면에서 지금 걷는 중인 사람에게 신청 → 수락하면 시작. Lv.50 맞춤 3대3(타워 규칙), 경험치 없음, 기록과 작은 BP.
- 배틀 엔진: 상대 쪽 선택(`foeChoice` · `foeSwitch` · 쓰러진 뒤 다음)을 AI 대신 상대 플레이어의 입력으로. 서버의 배틀 하나를 B에게는 좌우를 뒤집어 보낸다(beats의 me/it도).
- 턴: 둘 다 고르면 서버가 한 번에 계산. 기다리는 쪽은 롱폴링. 턴마다 30초, 넘기면 AI가 대신 고른다(두 번 연속이면 기권).

## 6. 단계

| 단계 | 서버 | 앱 | 끝났다는 기준 |
|---|---|---|---|
| M1 | `ActReq.app`, `/v2/team`, `greet`, `inbox`, news `hello` | 팀 타일 · 카드 · 순위 · 놀러 오는 동료 · 인사, news 하나씩 디코딩 | 테스트 ID 둘로 서로 보고 인사 |
| M2 | 교환 행동 · 두 세이브 트랜잭션 · 장부 · 교환 진화 | 제안 · 받기 · 수락 화면 | 테스트 ID 둘로 교환, 교환 진화 |
| M3 | 주간 보스 · 팀 HP · 기여 · 포획 | 레이드 로비 · 한 판 · 포획 | 테스트 ID 여럿으로 한 주를 당겨서 |
| M4 | 2인 배틀 · 롱폴링 · 타이머 | 신청 · 수락 · 2인 배틀 화면 | 테스트 ID 둘(맥 · 서버 쪽 스크립트) |
