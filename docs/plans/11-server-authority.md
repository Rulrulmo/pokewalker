# 11 서버 권위: 세이브는 서버가 만든다 (3.0)

> 2026-10-03 · **확정**(사용자: "A로 가자"). 10은 "앱이 만든 세이브를 서버가 검사한다"였다. 이 문서는 그걸 "앱은 행동만 보내고 서버가 세이브를 만든다"로 바꾼다.
> 서버 쪽은 `server/` 세션(미니 PC의 Claude), 앱 쪽은 릴리스 Mac의 Claude가 만든다. 이 문서가 둘 사이의 계약이다.

## 0. 정한 것

| 항목 | 결정 |
|---|---|
| 방식 | **A. 완전 온라인.** 앱은 "무엇을 했는지"만 보낸다. 서버가 앱과 같은 게임 코드(`Sources/Model`, `Sources/Battle`)와 **서버의 난수**로 결과를 계산해 세이브를 쓴다. 앱은 세이브를 보내지 않는다(`/v1/save` 없음) |
| 오프라인 | **걸음만 쌓인다.** 앱이 들고 있다가 연결되면 올린다. 레이더·배틀·타워·상점·도구·포켓몬 정리·코스 바꾸기는 "연결되면 할 수 있어요". 보기(도감·포켓몬·카드·상태)는 마지막으로 받은 서버 세이브로 |
| 옛 앱 | 3.0을 내는 날 서버가 2.x를 `426 old_app`으로 막는다. 2.x는 426을 받으면 바로 업데이트를 확인하므로 3.0을 받는다 |
| 2.x에서 못 올린 걸음 | 3.0 첫 실행 때 걸음 행동으로 올린다(서버의 상한 안에서) |
| 앱이 꺼지거나 PC를 바꾸면 | 새 세션이 시작되면 진행 중이던 레이더·야생 배틀은 끝난다(도망친 것과 같음). 타워 도전은 그 연승에서 끝난다. 지금 앱이 꺼질 때와 같다 |

## 1. 못 막는 것 (알고 간다)

- **걸음 입력 자체.** 키를 진짜 눌렀는지는 그 PC만 안다. 서버는 상한만 본다: 초당 15걸음, 하루 10만 걸음(서버가 날짜별로 **직접** 더한다, 10에서 앱의 `today`를 믿던 빈틈이 없어진다). 최대로 해 봐야 하루 5,000W.
- **자동 플레이.** 매크로로 배틀 버튼을 누르는 것. 결과는 서버가 정하니 얻는 건 손으로 한 것과 같다.
- **레이더 반응 시간.** 네트워크 지연 때문에 넉넉히 본다(3.2).

세이브를 고쳐서 W·포켓몬·도구·개체값·BP를 만드는 것은 **불가능**해진다. 앱이 세이브를 보내지 않으니까.

## 2. 구조

- 서버의 `trainers.walk`가 유일한 원본이다. 행동 하나 = 트랜잭션 하나 = `rev + 1`(바뀐 것이 있을 때). `history`(시간별·일별 사본, `pokeserver rollback`)는 그대로.
- 앱의 `state`는 서버 세이브의 **사본**(화면용)이다. 세이브가 바뀐 행동의 답에는 새 세이브 전체(`walk`)가 온다. 앱은 그걸 그대로 쓴다.
- **예측**: 앱은 같은 코드로 결과를 먼저 보여 줘도 된다(걸음의 W·경험치, 상자 정리처럼 난수가 없는 것). 답이 오면 서버 것으로 덮는다. 난수가 드는 것(배틀 턴, 레이더, 주운 것, 부화, 연쇄, 볼, 타워 상대, 날씨)은 답을 기다린다.
- **순서와 재전송**: 행동마다 `seq`(세션 안에서 1, 2, 3 …). 서버는 세션별 마지막 `seq`와 그 답을 기억한다.
  - 같은 `seq`가 다시 오면(답을 잃은 재전송) 다시 계산하지 않고 기억한 답을 그대로 준다. 상점에서 두 번 사는 일이 없다.
  - `seq`가 건너뛰거나 뒤로 가면 `409 {"error":"seq"}`. 앱은 다시 로그인해 세이브를 새로 받는다.
- 앱은 행동을 **하나씩** 보낸다(답이 오면 다음). 서버도 트레이너마다 하나씩 처리한다(SaveDB actor).
- 진행 중인 것(레이더, 배틀, 타워 도전, 배틀 중 묵힌 걸음)은 세이브가 아니라 서버의 `play` 표에 있다(4절).

## 3. API (v2)

모두 `POST`, `X-App-Key`, 본문 `{"id", "session", "seq", …}`. 로그인·새 ID·PIN은 v1 그대로(`/v1/login`, `/v1/create`, `/v1/pin`). 3.0은 로그인 답의 `walk`·`rev`를 그대로 쓴다.

**답**
- `200 {"rev": n, "walk": "<Walk JSON>"?, "news": [ … ], …행동별}` — `walk`는 세이브가 바뀐 때만.
- `422 {"error": "cannot", "why": "<한국어 한 줄>"}` — 지금 할 수 없는 행동(W 부족, 없는 도구, 잠긴 코스, 배틀 중 아님 …). 세이브는 그대로. 앱은 `why`를 LCD에 그대로 보여 줘도 된다.
- `400 bad_action`(형식 오류) · `409 replaced`(다른 PC) · `409 seq` · `403 pin_needed` · `426 old_app` · `404 no_trainer` — v1과 같은 뜻.

**news** — 서버가 이번 행동에서 일어나게 한 일, 일어난 순서대로. 앱은 홈 화면에서 하나씩 보여 준다(지금 홈에서 보여 주던 것과 같다).

| kind | 필드 | 앱이 보여 줄 것 |
|---|---|---|
| `find` | `item` | 동료가 주워 왔다 |
| `egg` | `dex`, `left` | 알을 주워 왔다 |
| `hatch` | `mon`(Mon JSON) | 부화 연출 |
| `weather` | `weather` | 날씨 변화 |
| `season` | `season` | 계절 변화 |
| `level` | `uid`, `level` | 레벨 업(동료: 5의 배수 알림) |
| `evolve` | `uid`, `from`, `to`, `shed`(Mon JSON?) | 진화 연출(토중몬 → 아이스크면 껍질몬도) |
| `learn` | `uid`, `move` | 기술 배우기(4개 미만이면 이미 배웠음: 알림만, 4개면 3.7의 `learn`을 기다림) |
| `unlock` | `course` | 새 코스 해금 |
| `dex` | `count` | 도감 달성(이벤트 코스·기기 색) |
| `chain` | `n`, `bonus`, `reward`? | 연쇄 이어짐(+2n W, 5연쇄마다 도구) |

### 3.1 걸음 `/v2/steps {"n": 걸음}`
- 앱은 쌓인 걸음(StepGate를 거친 것)을 **15초마다** 보낸다. 다른 행동 직전에도 먼저 보낸다(레이더가 W를 정확히 보도록). 오프라인이면 쌓아 둔다.
- 서버가 받는 수: `min(n, 지난 걸음 이후 서버 시각 × 15 + 600, 오늘 남은 몫)`. 오늘 몫은 서버가 KST 날짜별로 더한다(`steps_day`). 답의 `"taken": k`(깎였으면 n보다 작다).
- 그다음 서버가 `Walk.walk(k)`(W·경험치·알 걸음·레벨) → 날씨(`weatherDue`) → 동료 이벤트(`eventDue`: 주운 도구·알) → 부화(`hatchDue`) → 진화(레벨이 오른 것) → 해금. 모두 news로.
- 배틀 중이면 서버가 걸음을 묵혀 두었다가(`play.held`) 배틀이 끝날 때 적용한다(지금 앱의 `heldSteps`와 같음).
- 진화는 레벨이 오른 **그때** 서버가 한다(조건은 그 순간의 낮·밤, 가방, 장소). 앱은 홈에서 연출만 한다. 진화를 막는 B 캔슬은 지금처럼 없다.

### 3.2 레이더
- `/v2/radar` → `{"bush": 0-3, "window": 초, "chain": n}`. 연쇄 중이 아니면 10W를 낸다(없으면 422). 서버가 풀숲·포켓몬·창을 정해 `play`에 둔다. 포켓몬은 아직 알려 주지 않는다.
- `/v2/radar/pick {"bush": k}` → 맞는 풀숲이고 서버 시각으로 `1.5 + window + 3`초 안이면 배틀이 시작된다: `{"battle": Battle JSON, "beats": [Beat JSON]}`. 틀리거나 늦으면 `{"missed": true}`, 연쇄는 끝.

### 3.3 배틀 `/v2/battle {"cmd": …}`
- `cmd`: `{"fight": 칸}` · `{"ball": true}` · `{"item": "이름"}` · `{"swap": i}` · `{"replace": i}` · `{"run": true}` · `{"forfeit": true}`(타워).
- 서버가 `play.battle`에 그 턴을 돌린다(`Battle.turn`, 볼 종류 `Walk.rollBall`, 서버 난수) → `{"battle": …, "beats": […], "end": …?}`.
- 앱은 지금처럼 `from`(직전 Battle)에서 beats를 재생한다. 메뉴의 막힘(PP 0, 도발, 트집 …)은 앱이 미리 걸러도 되고, 서버도 같은 이유로 422.
- **끝**(`end`): 서버가 지금 앱의 `after()`를 한다.
  - 부활 도구가 있으면 쓰고 배틀이 이어진다(`end` 없음, beats에 회복).
  - 야생: 경험치·노력치를 돌려 쓴다(`writeBack`), 잡았으면 상자로, 묵힌 걸음 적용, 레벨·진화·기술 news. 잡거나 이기면 연쇄 판정 → 이어지면 `chain` news와 `"next": {"bush", "window", "chain"}`(다음 풀숲은 3.2의 pick으로).
  - 타워: 이기면 `towerWin`(BP) 다음 상대는 `/v2/tower`, 지면 `towerEnd`.
- `Battle`, `Fighter`, `SideState`, `Sky`, `Side`, `Beat`, `Move`, `ItemUse`는 Codable이 된다(공유 코드, S0).

### 3.4 배틀 타워
- `/v2/tower` → 도전 중이 아니면 참가비 50W를 내고 연승 0으로 시작, 도전 중이면 다음 상대. `{"battle", "beats"}`.
- `/v2/tower/pick {"slot": 0-2, "uid": n}` · `/v2/tower/pick {"reset": true}`(추천으로) — `towerSet`.

### 3.5 상점 `/v2/buy {"bp": bool, "item": 이름 | "legend": k | "shell": 이름, "qty": n}`
- `Walk.purchase`. 전설은 서버가 발급(지금 `/v1/buy`와 같은 굴림), 답의 news 없이 `"mon"`.

### 3.6 도구 `/v2/use {"item": 이름, "stat": 0-5?}`
- 이상한사탕 · 영양제 · 순백떡 · 열매 · 은색/금색병뚜껑(`stat`) · 진화의 돌(진화 news) · 파는 도구(전부 팔기, `"watts"`).
- `/v2/sell-all` — 우클릭 메뉴의 전부 팔기.

### 3.7 포켓몬 `/v2/mon {"op": …, "uid": n, …}` (자리 번호 대신 uid: 순서가 바뀌어도 틀리지 않게)
- `pair`(함께 걷기, 홈 스티커 클릭도) · `store`(상자로) · `fetch`(워커로) · `release`(놓아주기, W) · `release-dupes {"dex"}`(중복 놓아주기)
- `move {"slot", "move"}`(기술 바꾸기: `relearnable` 안에서만) · `learn {"slot": 0-3 | "skip": true}`(기다리는 기술) · `trade`(통신 진화)
- 3.0 첫 로그인 때 서버가 uid 없는 포켓몬에 uid를 붙인다.

### 3.8 코스 `/v2/course {"course": i}` — 열린 코스만(`unlocked`), 코스 걸음 0부터.

## 4. 서버 저장

| 표 | 내용 |
|---|---|
| `trainers` | `walk`(원본), `rev` — 그대로 |
| `play` (새) | `key`, `state`(JSON): 레이더(`bush`, `window`, `chain`, `at`, 포켓몬), 배틀(`Battle`, `kind`, 참가 uid), 타워 도전 중, 묵힌 걸음. 새 세션이 시작되면 지운다(0절) |
| `steps_day` (새) | `key`, `day`(KST), `n` — 하루 상한 |
| `actions` (새) | `key`, `session`, `seq`, `at`, `kind`, `reply` — 재전송에 줄 마지막 답, 그리고 14일치 기록(무슨 일이 있었는지 볼 때) |
| `mons` | 발급 장부로 계속 쓴다(서버가 직접 쓰니 검사용은 아님). `chains`·`grants`는 `play`로 대신한다 |

- 10의 세이브 검사(`SaveCheck`)는 3.0에선 필요 없다(세이브가 들어오지 않는다). 2.x를 막을 때까지만 둔다.
- 관리 명령(`show`, `walk`, `rollback`, `set`, …)은 그대로 쓴다. `pokeserver play <id>`(진행 중인 것)과 `pokeserver actions <id>`(최근 행동)을 더한다.

## 5. 앱 (3.0)

- `Walker`가 `state`를 바꾸던 곳(주로 `Core/Flow.swift`, `Core/Menu.swift`, 홈의 이벤트)은 행동을 보내고 답을 받는다. 답을 기다리는 동안 그 화면은 키를 받지 않고, 0.3초가 넘으면 작은 표시를 한다.
- 오프라인: 행동이 필요한 메뉴는 흐리게 하고 "연결되면 할 수 있어요". 걸음은 쌓인다(메뉴 줄에 "올릴 걸음 n").
- news는 홈에서 차례로 보여 준다(지금 홈 화면이 하던 순서와 같게).
- 앱이 굴리던 난수(`rng`)는 화면 효과(감정 표현, 연출)에만 쓴다.
- `state.json`은 보기용 캐시다. 1.x의 서명(`Sign.swift`)·`audit`·`refundBalls`는 3.0에서 뺀다.
