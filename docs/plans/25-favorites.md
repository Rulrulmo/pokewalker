# 25. 포켓몬 즐겨찾기 (5.2.1 후보)

> 사용자가 10-23에 정했다: "하다보니까 포켓몬 메뉴에 즐겨찾기 기능 있었으면 좋을것같긴한데 어때?" → "ㅇㅇ".
> 이 문서는 서버 설계다: 저장 칸, act, 보호, 옛 앱. 화면은 Mac이 시안을 그린다.
> 구현은 사용자가 시안을 본 뒤에 한다. 10-26 5.2 켜기가 안정된 다음이다. 설치 · 발행은 그때 따로 OK를 받는다.

## 1. 정한 것(요약)

| 항목 | 정한 것 |
|---|---|
| 저장 | `Mon.fav: Bool?`. 켜면 `true`, 끄면 `nil`이다(안 켠 포켓몬은 저장에 칸이 없다). |
| act | `.mon(op: .fav(uid: Int, on: Bool))`. 동반 · 워커 · 상자 어디에 있든 uid로 찾는다. |
| 체인 · 레이더 | 끊지 않는다(`.mon(.learn)`처럼). 배틀 중에는 다른 act처럼 "배틀 중이에요"다. |
| 남는 때 | 진화 · 폼 바꾸기 · 로토무 · 합체(안에 들어간 쪽도) · 지니기 · 기술 · 상자↔워커 · 맡겨 키우기 · 게시판에 올렸다 돌아옴 |
| 지워지는 때 | 다른 트레이너의 것이 될 때: 교환, 게시판 거래, 교환으로 받은 포켓몬 우편 |
| 서버 보호 | 중복 놓아주기에서 뺀다. 하나 놓아주기는 서버가 막는다. 교환 · 게시판 · 맡기기는 앱이 한 번 더 묻는다. |
| 옛 앱 | 5.2 이하는 칸을 모르고 무시한다. 저장은 서버가 만들기 때문에 칸이 사라지지 않는다. |
| 스위치 | 필요 없다. 서버 설치가 앱 발행보다 먼저면 된다. MIN_APP도 올리지 않아도 된다. |

## 2. 저장

- `struct Mon`에 `var fav: Bool? = nil`을 더한다(Optional이라 이 칸이 없는 옛 저장도 그대로 읽힌다).
- 끌 때는 `false`가 아니라 `nil`로 둔다. 그래서 즐겨찾기를 안 쓰는 사람의 저장 크기는 그대로다.
- 개수 제한은 없다. 동반 · 워커 3마리 · 상자 어디든 켤 수 있다.

## 3. act

```swift
enum MonOp { … case fav(uid: Int, on: Bool) }      // 5.2.1 (docs/plans/25)
// 보내는 모양: {"mon":{"op":{"fav":{"uid":1002521,"on":true}}}}
```

- uid가 내 포켓몬이 아니면 "그 포켓몬은\n없어요"다(`.hold`와 같은 문구).
- 이미 그 상태면 거절하지 않고 그대로 성공이다. 저장이 바뀌지 않으니 rev도 그대로다. 앱이 두 번 눌러도, 다시 보내도 괜찮다.
- 뉴스는 없다. 답의 `walk`에 바뀐 칸이 온다.
- 체인 · 레이더(EngineRules.act1):
  - `keepsChain`과 `keepsRadar`에 `.mon(.fav)`를 넣는다. 덤불이 떠 있을 때 눌러도 레이더가 꺼지지 않고, 체인도 그대로다.
  - 배틀 중 허용 목록(`.battle`, `.steps`)에는 넣지 않는다. 배틀 화면에서는 즐겨찾기 버튼을 숨긴다.
- 서버 `actName`에 `"fav"`를 더한다(actions 로그용).

## 4. 남는 때 · 지워지는 때

- 그대로 남는다(같은 Mon을 고치기만 해서 따로 할 일이 없다): 진화(`Walk.evolve`), 폼 · 로토무 · 비추는거울(`.form`, `.rotom`), 합체 · 분리(`fused` 안에서도 그대로), 지니기, 기술 바꾸기, 함께 걷기 · 상자로 · 워커로.
- 새로 생기는 포켓몬은 즐겨찾기가 꺼진 채로 나온다: 껍질몬(`Walk.shedinja`는 새로 만든다), 알, 잡은 것.
- 내 것인 채 잠깐 나갔다 오면 남는다:
  - 맡겨 키우기: 같은 Mon이 "visit" 우편으로 돌아온다.
  - 게시판에 올렸거나 제안했다가 내리거나 거절된 것: "returned" 우편으로 돌아온다.
  - 이 동안 남에게 보이는 화면(게시판 목록, 교환 제안, 친구 워커의 손님)에도 Mon JSON이 그대로 간다. 앱은 별 표시를 내 저장(`w.companion`, `w.caught`, `w.box`)에서만 그린다.
- 다른 트레이너의 것이 될 때는 지운다. 받는 쪽에서 지우고, 서버에서 이 두 곳만 고치면 된다.
  - `ServerClaims.adopt`: 게시판 거래, "trade" 우편
  - `ServerTrade.receive`: 1:1 교환
  - 둘 다 `m.ot = m.ot ?? giverName` 줄 옆에 `m.fav = nil`을 넣는다.
- 대전 · 레이드 · 탑 · 원정은 복사본으로 싸운다. 저장에 쓰는 것은 경험치 같은 값뿐이라 즐겨찾기에는 영향이 없다.

## 5. 보호

| 동작 | 추천 | 이유 |
|---|---|---|
| 중복 놓아주기 | 서버: 즐겨찾기를 뺀다 | 사용자 결정. 한 번에 여러 마리를 놓아주는데, 하나하나 보지 않는다. |
| 하나 놓아주기 | 서버가 막는다: "즐겨찾기한 포켓몬이에요\n먼저 풀어 주세요" | 되돌릴 수 없다. 다른 PC의 5.2 앱에는 별 표시가 없어서 앱이 묻는 것만으로는 못 막는다. |
| 교환 신청 · 수락, 게시판 올리기 · 제안 · 수락, 맡기기 | 앱이 한 번 더 묻는다("즐겨찾기한 포켓몬이에요. 보낼까요?"). 서버는 막지 않는다. | 그 포켓몬을 일부러 골라야 하고, 수락 전까지 취소 · 내리기가 된다. 맡기기는 돌아온다. 서버까지 막으면 5.2 앱 사용자가 이유를 모른 채 막힌다. |

- 중복 놓아주기:
  - `Walk.releaseDuplicates`의 거르는 조건에 `box[i].fav != true`를 더한다.
  - 앱이 보여 주는 "중복 n마리"도 같은 기준이어야 한다. 그래서 `Walk.releasableDuplicates(of:)` 하나를 두고 서버와 앱이 함께 쓴다.
  - 남기는 한 마리(가장 좋은 것)를 고르는 `duplicates(of:)`는 그대로 둔다. 즐겨찾기가 그 한 마리여도, 아니어도 즐겨찾기는 남는다.
- 하나 놓아주기:
  - `.release`에서 합체 검사 옆에 `if w.box[ref].fav == true { return "즐겨찾기한 포켓몬이에요\n먼저 풀어 주세요" }`를 넣는다.
  - 5.2.1 앱은 놓아주기 버튼에서 이 안내를 바로 보여 준다. Mac이 고를 수 있는 다른 방법은 "풀고 놓아주기"다: `.fav(on: false)`를 보낸 뒤 `.release`를 보낸다.
  - 5.2 앱(다른 PC)에서는 서버의 거절 문구가 그대로 뜬다. 5.2.1에서 풀면 놓아줄 수 있다.

## 6. 옛 앱 · 저장이 사라지지 않는지

- 5.2 이하 앱:
  - `Mon`은 Codable을 자동으로 만든다. JSONDecoder는 모르는 키를 무시하므로 `fav`가 있는 저장도 그대로 읽는다.
  - 옛 앱은 `.fav`를 보내지 않는다.
  - 화면에는 즐겨찾기가 안 보인다. 하나 놓아주기만 서버가 거절한다(§5).
- 칸이 사라지지 않는지:
  - 3.0부터 저장은 서버가 act로 만든다. 앱은 저장을 올리지 않는다(3.0 전 저장의 `legacy` 한 번만 예외).
  - 옛 앱의 로컬 `state.json`에는 칸이 빠진다. 하지만 다음 답의 `walk`가 서버 것이라 다시 채워진다.
  - 서버는 저장을 Walk로 읽어서 다시 쓰므로, 서버 바이너리가 `fav`를 알아야 한다. 그래서 서버 설치가 앱 발행보다 먼저다(§8).
- 되돌리기 주의:
  - 서버 바이너리를 5.2로 되돌리면 그 서버가 다시 쓰는 저장에서 `fav`가 사라진다(5.2의 `tms`와 같은 주의).
  - 잃는 것은 표시뿐이다. 포켓몬 · 아이템은 그대로다.

## 7. 스위치가 필요한지

필요 없다.

- 더하기만 하는 기능이다. 칸은 옛 앱에 보이지 않고, act는 5.2.1 앱만 보낸다.
- 서버의 새 거절(하나 놓아주기)은 5.2.1 앱이 켠 포켓몬에만 걸린다. 스위치로 켰다 껐다 할 행동이 없다.
- 순서만 지키면 된다: 서버 먼저, 앱 다음.
  - 옛 서버는 `.fav`를 모르는 act라 읽지 못한다.
  - 그래도 깨지는 것은 즐겨찾기 버튼 하나뿐이다. 앱은 거절로 받는다.
- MIN_APP 5.2.1은 필요 없다. 다른 PC의 5.2 앱이 별을 못 보는 정도라 급하지 않다. 다음 MIN_APP 때 같이 올리면 된다.
