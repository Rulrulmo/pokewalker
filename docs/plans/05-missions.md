# 05 · 의뢰 (일일 · 주간 미션)

> 상태: 기획안 (코드 변경 없음) · 대상: PokeWalker (Swift 6 + AppKit) · 작성 2026-09-30 · 의존: 없음. 진행 신호 `record(Deed)`를 06 업적이 같이 씀(→ 06-achievements.md). 공통 시스템은 → README.md.

## 1. 한 줄 요약 · 왜 재미있나

**매일 아침 엄마 · 요일 형제 · 오박사/공박사가 부탁을 하나씩 보내고(일일 3개 + 주간 1개), 평소처럼 일하면서 걷다 보면 저절로 채워진다.** 다 하면 W · 도구 · 가끔 BP를 받고, 7개마다 커트의 규토리 볼 스탬프를 찍는다.

- 지금은 "오늘 무엇을 할까"가 없다: 레이더 · 타워 · 도감은 늘 같은 자리에 있다. 의뢰는 **하루에 작은 목표 하나**를 준다("오늘은 물 타입 2마리만"). 잠깐 들여다보는 데스크 펫에 딱 맞는 크기.
- 절반은 **아무것도 안 해도 채워진다**(걸음, 동료 쓰다듬기). 나머지는 1~3분이면 끝나는 레이더 몇 판. 긴 세션을 요구하지 않는다.
- **벌 없음**: 연속 출석 보너스가 없고, 못 한 의뢰는 자정에 조용히 사라진다. 스탬프는 날짜와 상관없이 쌓이기만 한다. 주말에 쉬어도 잃는 게 없다.
- 기존 시스템을 골고루 건드린다: 날씨(타입 ×1.5), 연쇄, 도감 빈칸, 알, 타워. 의뢰가 "지금 이 코스에 가 볼까?"로 이어진다.

## 2. 원작(HGSS) 참고

## 3. 플레이 흐름

1. **자정 뒤 첫 틱** — `Walk.rollover`가 새 날을 열면 그날 의뢰 3개가 생긴다(주가 바뀌었으면 주간 1개도). 알림은 없고, 홈 수첩에 **편지 스티커**가 붙는다(읽으면 떨어짐).
2. **메뉴/홈 키 → 메뉴 타일 "의뢰"**(새 타일 — 자리는 README.md '메뉴 타일', 노트는 `완료 1/3` 또는 `받은 편지 1`) → LCD엔 고른 의뢰의 사람, 패널엔 목록.
3. **패널 줄 클릭 = 그 의뢰를 LCD에**(사람 그림 + 부탁 말, 진행 막대). ◀ ▶ 로 줄 이동, ↩ 메뉴로.
4. 평소대로 걷고 · 레이더 · 타워 · 쓰다듬기. 진행은 **저절로** 올라간다(따로 누를 것 없음).
5. **다 채운 순간 자동 지급**(W · 도구는 가방으로) + macOS 알림 "의뢰 완료 · 엄마: 5,000걸음! +80W". 홈에 돌아오면 `.say`로 한 번 더(레벨 업 메시지와 같은 줄서기).
6. 마음에 안 드는 의뢰는 줄의 **바꾸기**(하루 1번, 무료). 이미 진행한 것도 바꿀 수 있음(진행은 버림).
7. 7개 완료 → 커트 스탬프 한 장 → "커트: 규토리로 볼을 만들었어!" 볼 3개.

## 4. 규칙 · 수치 초안

### 4.1 기준값

- **하루 경계 = 실제 자정**(`Walk.day`, "오늘 걸음"과 같음). 주 = ISO 주(월요일 시작). 게임 속 하루(1,000걸음)는 하루에 10번 넘게 돌아서 의뢰 주기로는 너무 짧다.
- **M = 내 평소 걸음** = `history`(최근 7일)에서 0이 아닌 날의 중앙값. 기록이 없으면 5,000. 목표 걸음은 전부 M에 맞춤 → 타자량이 적은 사람도, 많은 사람도 같은 난이도.
- **노력 예산**: 일일 의뢰 하나 = 레이더 **8판 이하**(80W, 1,600걸음어치)로 기대값이 끝나야 함. 주간 = 25판 이하.
- 확률은 **실제 추첨 함수로 잰다**: 상태를 복사해 `course`를 바꾸고 `encounter(&r)`를 300번 → 그 코스의 타입 · 종 출현 비율 p. 다른 코스는 `courseSteps = 1000`으로(바꾸면 코스 걸음이 0부터라 A 그룹은 늦게 열림). 날씨 가중(×1.5)도 그대로 들어감.

### 4.2 일일 3칸

| 칸 | 누가 | 의뢰(가능할 때만 뽑음) | 목표 | 보상 |
|---|---|---|---|---|
| 1 | 엄마 | 오늘 N걸음 | M×0.7, 500단위, 1,000~30,000 | 목표÷20×0.3 W(10단위; M 12,000 → 8,500걸음 → 130W). 4번에 1번은 같은 값의 `Walk.shop` 도구 |
| 2 | 요일 형제 | 요일 타입 N마리 잡기 | N = clamp(round(8p), 1, 5) | 슈퍼볼×2 + 30W |
| 3 | 오박사 · 공박사 중 하나 | 아래 표에서 무작위 | | |

- 칸 2: 그 요일 타입의 p가 열린 코스 어디에서도 0.12 미만이면(초반엔 바위 · 고스트가 없을 수 있음) **지금 코스에서 p가 가장 큰 타입**으로 바꾸고 말도 바꿈("오늘은 ○○ 타입으로 해 줘"). 목표 코스가 지금 코스가 아니면 줄에 `추천: 푸른 호수`.
- 날씨 궁합은 설명 한 줄로: "안개 끼면 고스트가 잘 나와요".

칸 3 후보:

| 누가 | 의뢰 | 가능 조건 | 목표 | 보상 |
|---|---|---|---|---|
| 오박사 | 연쇄 N | 늘 | 3 (한 번 레이더에서 연쇄 3에 닿을 확률 45% → 평균 2.2판) | 하이퍼볼 + 50W |
| 오박사 | ○○ 보여 줘(그 종 잡기) | 열린 코스에서 p ≥ 0.12, **못 잡은 종 우선** | 1 | 하이퍼볼×2 |
| 오박사 | 야생 N마리 쓰러뜨리기 | 늘 | 3 | 좋은상처약×2 |
| 공박사 | 동료 쓰다듬기(홈에서 ●) | 늘 | 3 | 친밀도 열매 1(`ItemKind.berry`, +500걸음) |
| 공박사 | 동료 레벨 +1 | 다음 레벨까지 ≤ M×0.5 EXP | 1 | 40W |
| 공박사 | 알 부화 | 알이 있고 남은 걸음 ≤ M | 1 | 이상한사탕 |

- **넣지 않는 것**: 이로치(1/64) · 전설 · 연쇄 6 이상(연쇄 7은 판당 2.4%) 같은 **운 의뢰**, "상점에서 사기" 같은 잡일, 연승.
- 일일 보상 합계 ≈ 하루 W의 20~30%. W는 `watts`에만 더함(`earned`엔 안 더함 → 코스 해금 속도는 그대로, `chainReward`와 같은 규칙). 9,999를 넘는 W는 버려짐 — 칸 1이 W 최대치면 도구로 줌.

### 4.3 주간 1칸 (오박사, 월요일에)

| 의뢰 | 가능 조건 | 목표 | 보상 |
|---|---|---|---|
| 이번 주 N걸음 | 늘 | M×3.5, 1,000단위(평일 5일 중 3.5일치 → 4일만 일해도 됨) | 3BP + 200W |
| 새 종 N마리 도감 등록 | 열린 코스에 못 잡은 종이 p ≥ 0.05로 N종 이상 | 2 | 이상한사탕×2 |
| 연쇄 5 | 늘 | 5 (판당 15% → 평균 7판) | 5BP |
| 배틀 타워 N승(연승 아님) | 타워 1승 이상 해 봤음 | 5 | 5BP |

BP는 주간에만: 주 최대 5BP(타워는 한 판 1~2BP + 7연승마다 +3, 뮤츠 300BP라서 흔들리지 않는 크기).

### 4.4 커트 스탬프 (끊기지 않는 누적)

- 의뢰 하나 완료 = 스탬프 1(일일 · 주간 모두). **7개마다**: 커트의 규토리 볼 3개(요일마다 다른 볼, 7종 순환) — `ItemKind`가 이미 "…볼"을 ×1.5로 쳐서 바로 쓸모 있음(던질 땐 `ballKind`가 슈퍼볼 그림으로 그림).
- **28개마다**(약 2~3주): 은색병뚜껑 1개.
  - 편집 메모: 처음엔 여기서 규토리 볼 **기기 색** 7개(프렌드볼 → … → 스피드볼)를 줬지만, 06 업적이 같은 7개를 리본 보상으로 주고 있어서 기기 색은 06에 둠(06은 보상이 꾸미기뿐이라 기기 색이 핵심). 스탬프 누적은 06에 "의뢰 스탬프" 리본 줄로 이어짐. 반대로 할지는 README.md 열린 질문 3.
- 날짜와 상관없이 쌓이기만 함. 연속 보너스 · 초기화 없음.

### 4.5 뽑기 · 바꾸기

- 씨앗 = `questSeed`(세이브마다 한 번 무작위 — 03의 `trainerID`가 있으면 거기서 만듦, → README.md '시드 · ID') ⊕ 날짜 정수(yyyyMMdd) ⊕ 바꾼 횟수 → `Seeded`(SplitMix). **`hashValue` 금지**(Swift는 실행마다 다름) — 같은 날 같은 세이브면 늘 같은 의뢰(테스트 · 나중의 공통 의뢰에 필요).
- 칸 3은 후보 중 "가능 조건"을 채운 것만. 바꾸기는 같은 칸에서 **지금 것과 다른 종류**로.
- 의뢰는 만들 때 목표 · 보상을 **고정해 저장**(그날 도중에 M이 바뀌어도 그대로).

- UI: `Screen.quests(Int)`(고른 줄), `menuItems`에 "의뢰", `QuestModel` + `drawQuests`(SidePanel), `paneContent` 한 갈래, `pageTap` 코드 **5800+k 줄 / 5810+k 바꾸기**(쓰이는 범위와 안 겹침 — 기획별 범위는 README.md '패널 클릭 코드'), `homeKey()` · `press(3)` · `title()`에 한 줄씩, `Compose`에 LCD 장면.

## 6. 데이터 · 저장

`Walk`에 Optional 필드만 추가(옛 세이브는 nil로 읽힘). **`version`은 절대 올리지 않음** — `Store.load`가 `version`이 다르면 세이브를 버리고 `Walk()`로 시작함.

```swift
struct Quest: Codable, Equatable {
    var id: String            // "2026-09-30|0", 주간 "2026-W40|w" — 안정적인 이름(나중에 서버가 가리킬 수 있게)
    var who: String           // "mom" "sib" "oak" "elm"
    var kind: String          // "steps" "type" "species" "chain" "ko" "pat" "level" "hatch" "tower" "newdex" "weeksteps"
    var arg: Int              // 타입 번호 · 도감 번호 · 연쇄 길이 (없으면 0)
    var goal: Int, got: Int
    var watts: Int, bp: Int, items: [String]
    var done: Bool
}
// Walk:
var quests: [Quest]? = nil       // 오늘의 3개 + 이번 주 1개
var questDay: String? = nil      // quests의 일일분이 속한 Walk.key
var questWeek: String? = nil     // "2026-W40"
var questSeed: Int? = nil        // 세이브마다 한 번 (Int: JSON에서 UInt64 큰 수 피함; 03 `trainerID`가 있으면 그 값에서)
var rerolled: Int? = nil         // 오늘 바꾼 횟수
var stamps: Int? = nil           // 완료한 의뢰 누적
var questNews: [String]? = nil   // 홈에서 아직 말하지 않은 완료 (홈에 가기 전에 꺼도 안 사라지게)
```

- `kind`는 **enum이 아니라 String**: 새 버전이 만든 종류를 옛 앱이 읽어도 `Walk` 전체 디코딩이 깨지지 않음(모르는 종류는 진행 안 함). `Quest`에 나중에 필드를 더하면 그건 Optional로.
- 걸음 의뢰 진행은 저장된 `got`(`record`로 더함) — `today`를 직접 쓰지 않음(의뢰가 자정 뒤 첫 틱에 생기므로 사실상 같지만, 바꾸기로 새로 생긴 것은 그때부터 셈).
- 상태는 전부 `state.json` 한 곳. 창 · UI 기억(고른 줄)은 저장 안 함.

## 8. 멀티 확장 여지

지금 설계에서 미리 해 둘 것은 세 가지뿐: **① 의뢰 생성은 `(날짜, 씨앗, 상태 요약) → [Quest]` 순수 함수**, **② `Quest.id`는 안정적인 문자열**, **③ 진행은 `record` 한 곳**. 나머진 나중에.

1. **오늘의 공통 의뢰(서버 없음)**: 씨앗에서 `questSeed`를 빼고 날짜만 쓰는 4번째 칸 — 모두가 같은 날 같은 의뢰(Wordle처럼). 누구나 할 수 있게 "걸음(M 기준)" · "시작 코스 두 곳(상쾌한 들판 · 웅성웅성 숲)의 종"에서만 뽑음.
2. **자랑 코드**: 완료 요약을 짧은 문자열로 복사(`PW-0930 ●●● W40:2/5`) → 메신저에 붙여 넣기. 서버 없음.
3. **친구 코드 · 함께 하는 의뢰(작은 서버)**: 그룹 코드로 모인 사람들의 걸음을 합쳐 "이번 주 합계 50만 걸음 → 모두 3BP". 서버는 `POST {group, questId, got}` / `GET {group, questId}` 두 개면 됨(Cloudflare Worker + KV 정도). `Quest`에 `scope: String?`("solo" / "common" / "team")을 그때 Optional로 추가.
- 걸음은 키 입력이라 **자동 입력으로 쉽게 부풀림** → 순위 · 경쟁 보상은 만들지 않고, 협동 · 자랑만.

## 10. 리스크 · 열린 질문

**리스크**
- 초반(코스 2~3개)엔 타입이 적어 요일 타입이 자주 대체됨 → 대체 규칙이 곧 기본 동작이 될 수 있음. 가능 조건 검사를 셀프테스트에 넣어 "불가능한 의뢰"는 절대 안 나오게.
- 홈 `.say` 줄서기가 이미 계절 · 날씨 · 줍기 · 부화 · 해금 · 도감 · 레벨로 붐빔 → 의뢰 소식은 맨 뒤, 한 틱에 하나.
- 300번 모의 추첨 × 코스 수(최대 35)는 하루 한 번이라 가볍지만, 바꾸기 때도 돌면 한 번에 1만 번 → 코스별 p를 그날 한 번만 계산해 캐시(저장 안 함).
- 시스템 날짜를 바꾸면 의뢰를 다시 뽑을 수 있음 → 혼자 하는 게임이니 막지 않음(공통 · 팀 의뢰 때만 서버 날짜 기준).

**결정할 것 (추천 기본값)**
1. 다 채우면 **자동 지급**할까, **"받기" 버튼**을 누르게 할까? → **자동**(잊어버리는 보상이 없고, 잠깐 보는 앱에 맞음).
2. 하루 경계: **실제 자정** vs 게임 속 하루(1,000걸음)? → **실제 자정**(요일 형제가 실제 요일이라).
3. 목표 걸음: **내 중앙값 × 0.7** vs 고정 5,000? → **중앙값 × 0.7**.
4. 개수: 일일 3 + 주간 1이면 적당한가? → **예**(1단계는 일일 3만).
5. 자리: **새 메뉴 타일 "의뢰"** vs 트레이너 카드 4번째 탭? → **새 타일**(06 업적은 카드 탭을 써서 타일을 안 씀. 전체 자리는 README.md '메뉴 타일' — 13칸 2×7).
6. 바꾸기: **하루 1번 무료**? → **예**.
7. BP 보상은 **주간에만, 주 최대 5BP**? → **예**.
8. 스탬프 보상 = **커트의 규토리 볼 + 28개마다 은색병뚜껑**? → **예**. 볼 7색 기기 색은 06 리본 보상으로(README.md 열린 질문 3 — 이쪽으로 되돌릴 수도 있음).
9. 요일 형제 그림: **대역 트레이너**로 갈까, 이름 · 말만 두고 그림 없이 갈까? → **대역**(lass · youngster 등, 모두 Gen 4 그림).
10. 대량발생(종 의뢰 대상 ×2) 넣을까? → **3단계에 선택**(추첨 가중치 한 줄이라 싸지만, 출현 규칙을 건드림).
11. 새 의뢰 알림(아침)도 보낼까? → **아니오, 완료 알림만**(편지 스티커로 충분).
