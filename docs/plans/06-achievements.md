# 06 · 업적 · 리본 — 기획안

> 상태: 초안 (검토 전) · 의존: 없음 (1단계는 지금 있는 세이브 값만으로 판정). 01 체육관 여정 · 03 레이드 · 07 로그라이트(던전) · 04 포켓슬론 · 05 의뢰 스탬프가 들어오면 그 기록을 읽는 리본 줄만 더함(→ 각 문서, 공통 시스템은 README.md).

## 1. 한 줄 요약 · 왜 재미있나

**지금까지 해 온 일(걸음, 도감, 이로치, 연쇄, 타워)을 리본 40여 개와 트레이너 카드 ★ 5개로 보여 준다. 받으면 HGSS 볼 색 기기가 열린다.**

- **새로 할 일이 아니라 지금 하는 일의 기록**: 일하며 친 키 = 걸음이라서, 가만히 있어도 "하루 2만 걸음"이나 "100만 걸음" 리본이 스스로 온다. 잠깐 볼 때 받을 것이 생기는 앱에 맞다.
- **다음 목표가 보인다**: 리본마다 진행도(`18,240 / 20,000`)를 보여 줘서, 지금 막연한 "더 걷기"가 "오늘 2천 걸음만 더"가 된다.
- **기존 세이브도 바로 챙겨 줌**: 판정의 대부분이 이미 저장된 값(`total`, `owned`, `shinyOwned`, `bestChain`, `towerBest`, 상자 …)에서 나와서, 업데이트 첫 실행에 그동안의 기록만큼 리본을 소급해서 준다.
- **보상은 꾸미기만**: W·BP 경제(레이더 10W, 전설 9,999W / 300BP)는 건드리지 않는다. 받는 건 리본 그림, 카드 색, 기기 색.

## 3. 플레이 흐름

### 3.1 받을 때 (아무것도 안 눌러도)

1. 조건을 채우면 기록만 먼저 해 둠(배틀 중이어도).
2. **홈 화면으로 돌아왔을 때** LCD에 `리본을 받았다! / 하루 2만 걸음 리본` (도감 달성 메시지와 같은 `.say`, 3초 또는 버튼). 한꺼번에 여럿이면 `…외 2개`.
3. macOS 알림 "리본" 종류(기본 켬, 우클릭 → 알림에서 끔). 기기 색이 열리면 `스피드볼 기기 해금 · 우클릭 → 기기`.
4. ★이 늘면 한 줄 더: `트레이너 카드가 초록색이 되었다!`.

### 3.2 볼 때 — 트레이너 카드 네 번째 탭 "리본"

- 메뉴 → **트레이너 카드** → 패널 탭 `카드 · 최근 7일 · 알 · 리본` (지금 3개 탭 뒤에 하나; "트레이너 카드" 탭 글자는 `카드`로 줄여 4칸에 맞춤). 02 로켓단의 "이야기" 탭이 같이 들어오면 5칸 `카드 · 7일 · 알 · 리본 · 이야기`(→ README.md '트레이너 카드 탭').
- 리본 탭(LCD = 요약, 패널 = 격자). 칸 클릭 또는 ● → 그 리본을 LCD에 크게. ◀ ▶ 한 칸, ↑ ↓ 한 줄, ↩ → 리본 탭(요약) → 메뉴.

- 연쇄: 이어질 확률 `Walk.chainGoesOn`(85% → 8%p씩 ↓, 최저 35%)을 곱하면 5연쇄 14.6%, 8연쇄 0.85%, 10연쇄 0.10% (배틀에서 이기고 풀숲을 맞힌다고 칠 때). 그래서 5 · 8 · 10. 20연쇄는 사실상 불가능해서 넣지 않음.
- 이로치: 1/64, 연쇄할수록 `chainShinyOdds`로 좋아짐. 레이더 한 번에 평균 3~4마리를 만나서 첫 이로치는 레이더 20번쯤.
- 타워: 21·49는 원작의 타이쿤이 나오는 번째, 100은 원작 ★. 상대 레벨 = 파티 평균 + 연승÷3이라 Lv.100 파티면 상대도 Lv.100에서 멈춤 — 100연승은 어렵지만 가능.
- 기존 도감 보상(프리미어볼 15 · 럭셔리볼 50 · 이벤트·전설 코스)은 그대로 둔다. 리본으로 옮기지 않음.

## 6. 데이터 · 저장

`Walk`에 Optional 두 칸만 (옛 세이브는 키가 없으면 nil로 읽힘):

```swift
var ribbons: [String: String]? = nil   // 리본 id → 받은 날 yyyy-MM-dd ("" = 리본이 생기기 전에 이미 채운 것)
var tally: [String: Int]? = nil        // 다른 곳에 없는 기록: "hatched", "evolved", "caught"
```

- **`Walk.version`은 올리지 않는다** — `Store.load`는 버전이 다르면 세이브를 버림(= 사용자의 펫이 사라짐).
- id는 문자열이고 **한 번 정하면 바꾸지 않음**(이름·조건 글은 바꿔도 됨). 나중에 멀티에서 그대로 씀.
- 카운터를 필드 3개 대신 딕셔너리 하나로: 체육관 · 레이드 · 던전 기획이 자기 필드를 따로 두더라도, 리본용 작은 기록은 여기에 키만 더하면 됨.
- `theme`(기기 색)은 `UserDefaults`에 **배열 인덱스**로 저장됨 → 새 볼은 `shells` **끝에만** 붙임. 01 GS볼 · 02 로켓단 화이트 · 07 탐험대와 순서 · 이름 겹침을 함께 정할 것(→ README.md '선물 기기 색').

### 소급 (기존 세이브)

1. 처음 판정할 때 `ribbons == nil`이면: 지금 조건을 채운 리본을 전부 `""`(예전에)로 기록.
2. 팡파르는 한 번만 모아서: `리본 17개를 받았다! / 지금까지의 기록`. 알림은 보내지 않음(열자마자 배너 17개 방지).
3. 새 카운터 시작값: `caught = caught.count + box.count`(지금 가진 수 = 적게 잡은 값), `hatched = 0`, `evolved = 0`. 2단계 리본 설명에 "기록을 시작한 뒤부터"라고 적음.
4. 받은 날이 `""`인 리본은 LCD에 `예전에 받음`.

## 8. 멀티 확장 여지

지금 만들지 않는다. 나중을 위해 지금 지킬 것은 두 가지뿐: **id 고정**, **받은 날 저장** (6절에서 이미 함).

- **1차 (서버 없음) — 카드 교환**: 트레이너 카드를 짧은 코드(JSON → base64, 수백 바이트)로 복사 · 붙여넣기. 내용: 이름, ★, 리본 id → 날짜, 도감 수, 이로치 수, `towerBest`, 최근 7일 걸음, 누적 걸음. 받은 쪽은 카드 탭에 "친구 카드"로 읽기만. 리본 판정이 `Walk` 값의 순수 함수라서 무엇을 보낼지는 그 결과만 고르면 됨.
- **2차 (작은 서버) — 친구 코드**: 주 1회 카드 요약을 올리고 친구 것을 받음. "이번 주 걸음" 비교, **함께 받는 리본**(친구들 합계 100만 걸음 등).
- **치팅**: 숫자는 자기 신고라 쉽게 조작됨 → 순위 상품은 두지 말고 비교 · 자랑만. 필요해지면 그때 서버가 리본 대신 원본 값으로 다시 판정(같은 `value` 함수).

## 10. 리스크 · 열린 질문

**결정할 것** (굵게 = 추천 기본값)

1. **보상 범위** — 꾸미기만 / 리본마다 W·BP 조금? → **꾸미기만**(리본 · 카드 색 · 볼 기기 색). W를 주면 레이더 · 전설 가격 균형이 흔들림.
2. **보이는 곳** — 트레이너 카드 4번째 탭 / 새 메뉴 타일 "리본 수첩"(메뉴는 이미 다른 기획으로 13칸 — README.md '메뉴 타일') / 따로 "스티커 수첩" 홈? → **카드 탭**. 메뉴 격자와 화면 수를 안 늘림.
3. **걸음 기준** — 하루 1만 · 2만 · 3만, 누적 10만 · 100만 · 300만이 사용자 속도에 맞나? → **트레이너 카드 "최근 7일" 평균을 보고 확정**. 평균이 2만을 넘으면 한 단계씩 올림.
4. **★ 임시 조건** — 01 · 포켓슬론 기획 전엔 ★1 = 원작 코스 완주, ★3 = 하루 3만 걸음? 기획이 들어온 뒤 이미 받은 ★은? → **임시 조건으로 시작, 받은 ★은 유지**.
5. **소급 연출** — 한 번 모아서 보여 주기 / 조용히 기록만 / 하나씩 다? → **한 번 모아서, 알림 없이**.
6. **못 받은 리본 조건 공개** — 전부 공개 / 몇 개는 "???"? → **전부 공개**(진행도가 재미). 체육관 · 던전 리본은 그 기능이 생길 때만 목록에 나옴.
7. **리본 회수** — 조건을 잃으면(Lv.100을 놓아줌) 없앨까? → **절대 안 없앰**.
8. **포켓몬 단위 리본** (원작처럼 포켓몬 페이지에) → **3단계로 미룸**. 트레이너 리본만으로 먼저 반응을 봄.
9. **타워 21 · 49번째에 타이쿤 Palmer 등장** — 이 기획에 넣을까? → **넣지 않음**(타워 규칙 변경은 따로). 리본 이름만 원작에서 빌림.

**리스크**

- Swift 6: 전역 `let ribbonList`에 클로저가 있으면 `@Sendable`이어야 컴파일됨.
- 1초마다 상자 전체를 도는 판정(Lv.100 · 510 · 6V · 단짝): 상자 수천 마리라도 1ms 아래. 느려지면 세이브 때(60초)만 판정.
- 기기 색 인덱스: 볼을 배열 가운데 끼우면 사용자가 입고 있던 색이 바뀜 → 끝에만 추가(6절).
- 목록이 길어지면(3단계에서 42개를 넘으면) 패널 한 페이지를 넘음 → 그때 도감 격자의 페이지 넘김(`pager`)을 그대로.
